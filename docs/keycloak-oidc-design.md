# Keycloak OIDC 登录与账户改造设计

本文记录用户已确认并授权实现的设计。当前接口契约见 `doc/API.md`，部署和账户迁移步骤见 `docs/keycloak-setup.md`。

## 已确认的边界

- Keycloak OIDC 完全替换本地密码登录；本站保留用户资料、部门、角色及业务权限。
- 后端完成授权码登录，建立本站 Cookie 会话；前端不保存访问令牌。
- 新用户通过统一认证后，提交有效注册票据并完善资料，取得本站成员资格。
- 保留已有本站用户 ID、部门和项目关系；通过维护命令显式绑定旧账户，不按用户名或邮箱自动合并。
- 首次准入可预填 Keycloak 资料，之后不自动覆盖本站用户名、手机号、邮箱或头像。
- 退出仅退出本站；取消本站“记住我”，闲置超时默认 30 分钟、可配置；不做 Keycloak 端禁用或退出后的即时本站会话撤销。
- 使用已有 Keycloak，凭据和部署地址使用环境变量配置。

对应的背景和取舍见 [认证边界](adr/0001-keycloak-authentication-boundary.md)、[账户绑定](adr/0002-explicit-identity-linking.md)和[会话生命周期](adr/0003-local-session-lifecycle.md)。

## 登录、准入与权限

采用 Spring Security 的 OAuth2 Client / OIDC 支持，使用授权码流程及 PKCE，校验 ID token 的签名、issuer、audience、时效和 nonce。登录请求的 state 与发起请求的服务器会话绑定，回调完成后更换会话 ID；不照搬参考代码的自定义 HMAC 凭证或通过 URL 传递本站 token 的方式。

前端区分三个状态：未认证、已通过 OIDC 但待准入、已关联本站用户。待准入访问者只能访问身份状态、资料预填、注册和退出等准入相关接口，不能读取用户列表、项目或其他业务数据。已绑定用户直接进入原目标页面；待准入访问者进入注册页面，完成注册后建立包含本站用户 ID 的业务身份。

业务代码按本站用户 ID 解析当前用户，不再通过 OIDC 用户名查找本地账户。本站权限继续由本地部门和项目关系判定，不从 Keycloak 的角色声明自动赋权。

首次注册保留本站用户名、手机号、可选邮箱和票据，移除密码输入。用户名、手机号冲突返回明确错误；存在旧账户时提示联系维护者绑定，而不允许通过注册取得该账户。注册在一个事务中创建用户、部门身份和 OIDC 绑定，并以唯一约束阻止重复或并发关联。

注册票据沿用现有有效期、部门、角色及可重复使用的语义，本次不改为一次性票据。已有用户不会因再次登录而重新使用票据或改变部门身份。

## 接口设计

全部新增认证路径放在 `/api/auth/` 下，适配现有 nginx 和 Vite 的同源代理。

| 接口 | 行为 |
| --- | --- |
| `GET /api/auth/login` | 发起 OIDC 登录；可接受经过校验的本站相对返回路径。 |
| `GET /api/auth/oidc/authorize/keycloak` | Spring Security 授权请求入口。 |
| `GET /api/auth/oidc/callback/keycloak` | 接收授权回调，完成身份校验并跳转到业务页或准入页。 |
| `GET /api/auth/status` | 返回未认证、待准入或已有本站用户的状态；预填资料仅在对应认证会话中提供。 |
| `GET /api/auth/csrf` | 为前端取得当前会话的 CSRF token。 |
| `POST /api/auth/register` | 要求已通过 OIDC；提交资料和票据后注册并绑定，不再接收密码。 |
| `GET /api/auth/me` | 保留已有用户资料响应；未认证返回 401，待准入返回 403。 |
| `POST /api/auth/logout` | 作废本站会话及 Cookie，返回 204；不调用 Keycloak 全局退出。 |

原 `POST /api/auth/login` 密码登录入口移除，资料、头像和业务接口继续使用本站 Cookie 与现有响应结构。写入请求启用 CSRF 校验，前端统一附带 CSRF header，并在登录或退出改变会话后重新取得 token。

OIDC 登录失败、用户取消、state/nonce 不匹配或令牌不合法时，不建立可访问业务的身份，返回可重试的登录页面。返回路径只允许本站相对路径，防止任意站外跳转。Keycloak 不可用时显示明确登录失败；已有本站会话按自身生命周期运行，不在每次业务请求中调用 Keycloak。

## 数据库与旧账户绑定

在现有 V13 之后新增 Flyway migration，创建专用身份绑定表，记录本站用户 ID、issuer 和 subject。对 issuer/subject 组合及本站用户 ID 设置唯一约束，形成本站用户与当前统一身份的一对一关联。不把开发数据中的随机 `user_cloaks.cloak_id` 当成真实 Keycloak 身份。

保留原有用户和所有业务外键；密码字段允许为空，新注册用户不写入密码。原有密码哈希不再参与任何认证，本次不批量删除历史值。移除密码认证链路和生产密码管理员初始化。

一次性维护命令读取绑定文件，仅在维护模式运行数据库迁移和身份绑定，不开放 HTTP 服务，也不运行开发数据或管理员初始化器。导入前检查用户存在、issuer 匹配当前部署、身份与账户不冲突；同一对应关系可重复执行，任何冲突均拒绝，整批事务回滚，不覆盖已有绑定或更改部门权限。

维护者先为已有管理员绑定身份，再开放新版登录入口；其余旧用户按确认过的对照表迁移。旧用户未完成绑定前不能凭同名 Keycloak 身份进入旧账户，也不会丢失已有业务数据。

## 首个管理员

全新部署通过配置指定首个管理员的 Keycloak subject，issuer 使用本站配置的认证服务。仅当尚无本站管理员且经过 OIDC 验证的身份与配置完全一致时，允许该身份完善资料后免票据创建首个 `ADMIN/LEADER` 用户；不使用固定假手机号或默认密码，不把首个登录者自动设为管理员。

已有管理员通过维护命令绑定，保留既有权限。配置不会把已关联的普通用户自动升级为管理员，也不会重置已有管理员资料。后续管理员授予仍属本站权限管理，不由 Keycloak 角色自动同步。

## 部署与验证

提供 issuer、client ID、client secret、本站公开 URL、会话闲置超时和可选首个管理员 subject 的环境变量示例。说明 Keycloak confidential client、授权码流程、PKCE、回调白名单及 `openid profile email` scope 的配置；回调使用明确的公开地址，避免内部容器地址或代理 Host 影响回跳。

生产会话 Cookie 使用 HttpOnly、Secure 和适合授权回跳的 SameSite 属性；开发 HTTP 环境单独配置。沿用当前服务器内存会话，后端重启后需重新登录，本次不引入共享会话基础设施。禁止日志记录授权码、令牌、Cookie 或 client secret。

后端验证覆盖 OIDC 成功和失败、待准入隔离、票据注册、唯一身份与并发约束、旧账户绑定冲突及回滚、首个管理员边界、CSRF、会话超时与仅本站退出。既有用户、权限和项目测试随身份解析方式更新，并运行完整后端测试；前端验证三态路由、注册、登录、退出和资料行为，运行类型检查及生产构建。

无真实 Keycloak 配置时使用受控 OIDC provider 验证协议交互，并提供真实环境联调步骤；不能把模拟验证表述为已经完成真实服务联调。
